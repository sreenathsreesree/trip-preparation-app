## Why a development build (not Expo Go)

This project uses **Expo SDK 58**. The Expo Go app from Google Play only supports one SDK at a time,
and at the time of writing Expo's own announcements said the SDK 58 version of Expo Go would reach
the stores "within a few weeks" of the SDK 58 release. Do not assume the Play Store Expo Go can open
this project — check the SDK version shown in Expo Go first. (If it does show SDK 58, `npx expo start
--go` will work too, but the development build below is the supported path.)

A **development build** is our own debug APK (`Trip Prep` with the Expo dev launcher built in). It
contains exactly this project's native modules and loads JavaScript from your computer's dev server.

## Build the development APK

```bash
npm run build:android:dev
# = npx eas-cli@latest build --platform android --profile development
```

- On the first Android build EAS asks to **generate a new Android keystore** — answer **yes**; EAS
  stores it for you. Reuse it for all future builds.
- The build runs in the cloud (free tier builds can queue). When it finishes, the CLI prints a build
  URL and a QR code; the build is also listed at expo.dev under the project's **Builds**.
- Only rebuild when native things change: new native packages, `app.json`/plugin changes, icons,
  splash, or the package name. JavaScript/TypeScript changes do not need a new APK.

## Install the APK on your phone

1. On the phone, open the build URL (or scan the QR code) and tap **Install** / download the `.apk`.
2. Android will ask to allow installs from that source (e.g. Chrome → *Install unknown apps* →
   **Allow from this source**). Then open the downloaded file and tap **Install**.
   Play Protect may warn about an unrecognised developer for sideloaded debug builds — choose
   **Install anyway** only for builds you started yourself.
3. Alternatively, with USB debugging enabled: `adb install path/to/app.apk`.

## Connect to the development server

1. Put the phone and computer on the **same Wi-Fi network** (guest/office networks often block
   device-to-device traffic).
2. On the computer: `npm start`. Because `expo-dev-client` is installed, the server starts in
   development-build mode and shows a QR code.
3. On the phone, open **Trip Prep**. The dev launcher lists servers found on the network — tap yours —
   or scan the QR code with the phone's camera.

If it cannot connect:

- Allow Node/port **8081** through the computer's firewall.
- Use a tunnel: `npx expo start --tunnel` (installs `@expo/ngrok` on first use).
- Use USB: connect the phone with USB debugging, run `adb reverse tcp:8081 tcp:8081`, start with
  `npx expo start --localhost`, then connect from the dev launcher.

Shake the phone (or press `m` in the terminal) for the developer menu; JS edits reload live.

## Optional: standalone preview APK

`npm run build:android:preview` builds a release APK with the JavaScript bundled in. It runs without
a computer, which is useful for testing cold starts and persistence the way users will experience it.
Installing it replaces the development build (same package name), so local data is kept as long as
both were signed by the same EAS keystore.

## Where data lives on Android

- SQLite file: `/data/data/com.sreenathsreesree.tripprep/files/SQLite/trip-prep.db` (plus `-wal` /
  `-shm` files). App-private internal storage: no permissions needed, not visible to other apps.
- Item and category photos: copied into `/data/data/com.sreenathsreesree.tripprep/files/inventory-images/`
  (the original stays in your gallery; the app keeps its own private copy, and deletes it when no
  item or category uses it any more).
- Survives app restarts, force-stops, phone reboots and app updates (same package and signing key).
- Removed by **uninstall** or **Settings → Apps → Trip Prep → Storage → Clear storage**.
- Android Auto Backup is left at the default (enabled), so trips can be restored when the app is
  reinstalled on a device signed into the same Google account. There is no cloud sync in the app.
